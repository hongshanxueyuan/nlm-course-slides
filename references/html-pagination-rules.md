## 任务描述

基于下方文档内容，对现有 Markdown 教学正文进行高质量分页，输出页面边界清晰、结构明确、可直接序列化为 canonical Markdown 的页面内容。

## 核心要求

### 1. 内容规划与去重（最重要）

#### 页面规划原则

* **内容完整性**：同一段原文内容应在一个页面内完整展示，避免拆分重复。
* **信息独立性**：每个页面必须包含独特的信息价值，不能简单重复其他页面内容。
* **逻辑层次**：确保页面间逻辑关系清晰，避免内容交叉重叠。
* **顺序保持**：页面顺序必须与原文顺序一致，不得重排。

#### 页面划分策略

* **单一主题页面**：适合包含 3-5 个相关要点的内容。
* **对比页面**：适合展示两个或多个概念的对比。
* **流程页面**：适合展示步骤性内容。
* **混合页面**：适合复杂但相关的内容组合。

#### 去重检查清单

* [ ] 每段原文内容最多只能被一个页面引用。
* [ ] 没有同一内容被拆分为多个页面重复展示。
* [ ] 每个页面都有明确的主题和独立价值。
* [ ] 页面间逻辑关系清晰，无内容交叉。
* [ ] 不在句中、段中任意截断，优先在逻辑单元之间分页。

#### 本节要点 / 总结 / 收尾（仅单页）

* 原文若出现**本节要点、总结、复盘**等收尾性内容：**必须放在全稿最后一页，且只占一页**（禁止拆成多页）。
* **主标题**：含「本节要点」时，**必须且只能是** **`## 本节要点`**；仅当原文**没有**「本节要点」、小节名明确为「总结」时，用 **`## 总结`**。
* **条目数量**：该页列表 **至多 5 条**要点；若原文超过 5 点，**合并同类、压缩语言**写进 5 条内，**不增页**。
* **禁止写入正文**：**不要**输出「**想一想：**」「**马上做：**」「本周行动」及同类收尾行动/反思句。

### 2. 页面结构与内容

#### 标准页面结构

```markdown
## 页面标题
- 要点1
- 要点2
- 要点3

> **重要概念**：核心定义（可选）
**关键指标**：85.6%（可选）
```

#### 内容控制

* 每页最多包含 3-5 个要点，避免内容过多。
* 优先使用无序/有序列表（`-` / `1.`）。
* 关键信息用 `**粗体**` 或 `*斜体*` 突出。
* 不生成开头页、结尾页、文件名页或额外封面页，避免冗余内容。
* 不要根据文件名、`output_name`、`md_name` 或 section 标题再额外生成一个包裹性的文档总标题。
* 页面如果有表格，表格内容行数与其他要点、标题行数**合计至多 6 点**；如果超过，则**合并同类、压缩语言**写进 6 点内。
* 最终总页数**不得超过 20 页**；若初步划分页数超过 20 页，优先合并相邻且逻辑相近的内容，而不是输出第 21 页及之后的页面。
* 输出的每个页面正文都**不要包含** `第 x 页` 这类页码标记；页码标记由下游序列化步骤统一添加。

#### 结构保持

* 标题尽量与其后紧邻内容保持在同一页。
* 列表、表格尽量不要从中间拆开；除非没有更合适的分页方式。
* 不要引入原文中不存在的 HTML 标签、额外包装块或新的章节标题。

### 3. 质量要求

* **信息准确**：紧扣原文，不虚构、不遗漏核心要点。
* **语言简明**：表达清晰，便于企业员工学习。
* **专业简洁**：风格专业、简洁、统一。
* **重点突出**：避免信息堆砌，突出重点。
* **最小改写**：这是分页与结构化任务，不是重新写一版新稿。

### 4. 原文引用

每页内容都必须直接来源于原文，不得脱离原文新增事实，也不要丢失原有标题与关键结构。

## 文档内容

```markdown
{text}
```

## 输出格式

请严格按照任务要求输出 JSON，格式如下：

```json
{"pages":["第 1 页正文","第 2 页正文"]}
```

要求：

* `pages` 按最终页面顺序排列。
* 每个字符串只包含该页正文，不包含 `第 x 页` 标记。
* 不要输出 JSON 之外的解释性文字。
